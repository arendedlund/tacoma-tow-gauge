# Implementation Plan: CAN Bus Gauge Display

**Branch**: `001-can-panda-display` | **Date**: 2026-05-14 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/001-can-panda-display/spec.md`

## Summary

Build a 4-phase in-vehicle gauge display for a Toyota Tacoma that shows engine oil
temperature, ATF pan temperature, and torque converter outlet temperature on a Microtips
AWL-2801424T70N01 (280×1424 px MIPI bar display) mounted in a custom steering column
clamshell. Phase 1 uses a comma.ai panda + Cabana to reverse-engineer the Tacoma's CAN
frame IDs and signal formulas. Phase 2 is a bench/vehicle demo with a Raspberry Pi CM5
driving the display via panda USB. Phase 3 removes the panda and connects the CM4
directly to the vehicle CAN bus (non-OBD-II tap point TBD). Phase 4 is the permanent
installation with a printed enclosure and key-on power.

## Technical Context

**Language/Version**: Python 3.11+

**Primary Dependencies**:
- `python-can` — CAN bus abstraction (panda USB in Phase 2; SocketCAN/MCP2515 in Phase 3+)
- `panda` (comma.ai) — USB interface to panda device (Phase 1–2 only)
- `pygame` — framebuffer display rendering
- `systemd` — service lifecycle, supervised startup/shutdown

**Storage**: Read-only overlayFS root (no corruption on key-off); separate small RW
partition for `config/thresholds.json` and `config/signals.json`

**Testing**: Manual hardware testing on bench rig and in-vehicle; CAN frame injection
via panda for signal decoder unit validation; no automated test suite in v1

**Target Platform**: Raspberry Pi CM5 (1 GB RAM) running Raspberry Pi OS Lite 64-bit;
MIPI DSI display via CM4 DSI connector; CAN via SPI MCP2515 + TJA1050 transceiver
(Phase 3+); USB host for panda (Phase 2)

**Project Type**: Embedded Linux application (single-board computer, vehicle-mounted)

**Performance Goals**:
- Boot to first display frame: ≤ 10 s (SC-006); target 8 s with service optimization
- Signal update latency: ≤ 2 s from CAN frame to display update (SC-003)
- Display frame rate: 30 fps target; 10 fps minimum acceptable

**Constraints**:
- Total device draw: < 1 A from 12V vehicle rail (WSH circuit, 25A fused)
- Requires automotive-grade 12V→5V DC-DC converter (not linear regulator)
- Root filesystem MUST be read-only (overlayFS) to survive key-off power loss
- OBD-II port MUST remain free in Phase 3+ (FR-009)

**Scale/Scope**: Single-device firmware; 3 temperature channels; 1 display

### Source Code (repository root)

```text
src/
├── main.py              # Entry point; wires subsystems together
├── can/
│   └── reader.py        # CAN bus thread; reads frames, dispatches to decoders
├── signals/
│   ├── __init__.py
│   ├── loader.py        # Loads signal definitions from config/signals.json
│   └── decoder.py       # Decodes raw CAN frames → GaugeSignal values
├── display/
│   ├── __init__.py
│   ├── renderer.py      # Renders DisplaySlots to pygame surface / framebuffer
│   └── slot.py          # DisplaySlot data class and state-to-color mapping
└── config/
    └── loader.py        # Loads thresholds.json; validates schema

config/
├── signals.json         # Signal definitions (arbitration IDs, PIDs, formulas)
└── thresholds.json      # Per-signal warning/critical thresholds

systemd/
└── gauge.service        # systemd unit for autostart on boot
```

**Structure Decision**: Single-project layout. No backend/frontend split — this is a
single embedded process with a CAN reader thread and a display render loop in the same
application, communicating via in-memory GaugeSignal objects under a lock.

## Phase 1 Resources

Before the panda arrives, these resources accelerate CAN signal research:

| Resource | Location | Use |
|---|---|---|
| commaai/opendbc Toyota DBC | `opendbc/opendbc/car/toyota/toyota_nodsu_pt_generated.dbc` | Identify broadcast frame IDs for signals that don't need OBD-II requests; cross-reference Cabana captures |
| Cabana (commaai) | Open source; install from GitHub | Log and visually decode CAN frames captured via panda |
| Toyota TIS ($15/48h) | techinfo.toyota.com | Wiring diagrams for Phase 3 CAN tap point (buy when starting Phase 3 planning) |

**opendbc note**: The DBC covers broadcast powertrain frames only. Enhanced Mode 22 PIDs
(0x1627 ATF pan, 0x1628 TC outlet) are request/response pairs not present in the DBC.
Verify those with a live panda query during Phase 1.
